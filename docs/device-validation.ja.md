# Quest 3の導入記録と確認手順

現在のAPKの版と検査結果は[Questプロトタイプ](quest-prototype.ja.md)を参照してください。導入ツールはPython 3.12以降と、Unityに同梱されたAndroid SDKを使います。

## 0.6.0の導入

2026-11-02、Wi-FiのADB経由で0.6.0を `adb install -r` により導入しました。導入済みパッケージのversionCode 6 / versionName 0.6.0と、Activityの起動成功を確認しています。APKのSHA-256は `acbad92c56aa72dfcf4862a5307d4680a4fb3a6876466ea5d822bea3fa055ddf` です。

新機能は[0.6.0の操作](modern-controls.ja.md)を参照してください。音声は起動時ON、初期モデルはReazonSpeechで、SenseVoiceへ切り替えられます。空間データの許可と部屋設定が必要です。導入・起動成功だけでは、ReazonSpeechの認識精度、手追跡、VR移動、部屋への衝突の実機合格とはしません。

0.6.0の同一プロセスのログで、境界非表示、空間データ許可、`ROOM_COLLISION_READY geometry=mesh count=1` を確認しました。ReazonSpeechによる認識完了も2件あり、音声0.65秒／0.55秒に対するデコードは各0.06秒でした。これは短い入力の処理時間で、精度の評価や発話終了から表示までの遅延ではありません。保存済み部屋メッシュのCollider生成は確認できましたが、実際の壁・机に文字が当たる見え方、手操作、VR移動、2台通信は未判定です。収集範囲に0.5.0のSphereCollider未検出エラーの再発はありません。

## 0.5.0で確認した内容

2026-11-02にQuest 3（Android 14 / API 34）へ0.5.0をUSB経由で導入し、起動とアプリPIDに限定したログ取得に成功しました。APKのSHA256は `7edda2d26e3059d2308a7b8ff054d9d895c97706f392ef5ad9450b509a2a12cb`、導入済みパッケージはversionCode 5です。ログでパススルー初期化成功と `Boundary is invisible` イベントを確認しました。その後、無線ADBを有効化し、Wi-Fi経由のログ取得にも成功しています。

ユーザーから「パネルが見えて、話した文字も出る」と実機での確認を得ました。マイク権限は許可済みで、取得ログには音声認識2件（音声0.49秒→処理0.09秒、音声0.52秒→処理0.10秒）があり、初回起動と同じプロセスが継続しています。この2件は短い音声の認識処理時間だけで、無音判定・待ち行列・描画を含む遅延や長時間性能を示しません。認識精度の定量評価、スリープ復帰、VR切替、2台通信は未判定です。

初回起動では `CreateAlignmentMarkers()` の `CreatePrimitive(Sphere)` に対して `SphereCollider` が存在しないエラーも記録されました。起動は継続していますが、Androidビルドでの型除去とマーカー表示を要調査です。またAssetPackManagerのクラス未検出とOVRMetricsToolのバージョン解析エラーがあります。ログ取得成功を全機能の動作合格とは扱いません。生ログと端末情報は `.work/quest-device/` に保存し、公開Gitには含めません。

## 導入と起動

Quest 3の開発者モードを有効にしてUSB接続し、ヘッドセット内でこのPCからのUSBデバッグを許可します。リポジトリルートで実行します。

```powershell
python tools/quest_device.py status
python tools/quest_device.py install
python tools/quest_device.py launch
```

`status`は端末一覧を表示するだけです。`install`はローカルAPKの署名・必須マニフェスト項目・ARM64・モデルとライセンスを検査してから、アプリデータを保持する `adb install -r` を実行します。`launch`はインストール済みアプリの起動Activityを端末から解決して起動します。マイク許可はアプリ内で操作してください。

複数のAndroid端末が接続されている場合、`status`のserialを使い、各操作に `--serial SERIAL` を指定します。未承認・オフライン・Quest 3以外と報告された端末には導入しません。許可の強制付与、アプリデータ削除、署名不一致時のアンインストールは行いません。

Unityの場所が異なる場合は、`--android-player 'C:\...\Editor\Data\PlaybackEngines\AndroidPlayer'` を指定します。APKを別の場所に置いた場合は `--apk 'C:\...\Koekatamarin2026.apk'` を `install` に指定します。

## まず1台で確認

| 操作 | 確認すること |
| --- | --- |
| 初回起動 | アプリが終了せず、現実のパススルーと日本語UIが見える。右ポインターとボタンが動く |
| MR | 境界表示抑制の要求がOSに受理されるか。境界が残った場合も、その状態とQuest OS版を記録する |
| サンプル発射 | 文字が飛び、約5秒で消える。Aでパネルが隠れ、Bで正面へ戻る |
| 起動時の音声自動ON、許可拒否 | 操作不能にならず停止表示になる。許可を変更した後に再操作できる |
| 起動時の音声自動ON、許可 | 初回のモデル展開が終わり、聞き取り状態になる。追加モデル取得のためのインターネット接続は不要 |
| モデル切替 | ReazonSpeechとSenseVoiceを同じ文で比較する。音声OFF中の切替はOFFを維持する |
| 手操作とVR移動 | 右人差し指ピンチで選択、右中指でパネル呼戻し。VRで左スティック／左ピンチ移動、30度回転が動く |
| 5層と衝突 | 横から文字の厚みを確認する。部屋読込後にMRの壁・机へ、VRで地面へ文字を飛ばす |
| 日本語 | 「こんにちは」「ありがとう」「コエカタマリン」を各10回。表示内容、抜け、重複を記録する |
| 繰り返し・無音 | 同じ語を2回言うと2回発射する。無音・生活音で誤射出しないか調べる |
| 長い発話 | 6秒を超えて話し、分割と待ち時間を確認する |
| 音声OFF | マイクと待機中の発射が停止する。OFF/ONを繰り返して復帰できる |
| MR→VR→MR | VRは境界の復帰を確認してから夕日の風景を表示する。MRへ戻ると風景が消え、パススルーへ戻る |
| スリープ・復帰 | 録音とLAN接続が停止する。0.6.0は音声がONだった場合のみ復帰時に録音を再開し、手動OFFは維持する。LANは再接続する。MRのパススルーと境界状態も再確認する |

実行前に、装着した人が周囲を確認できる場所で、通常のQuest操作により境界設定を確認してください。境界抑制の要求と実際のOS状態は別です。Editorの模擬境界応答はこの項目の合格根拠になりません。

## 2台で確認

両方に同じAPKを導入し、同じWi-Fi・部屋番号で接続します。[位置合わせ手順](shared-space.ja.md)に沿って共通のA・Bを指定します。

| 操作 | 確認すること |
| --- | --- |
| 各端末から接続 | 相手1台と表示され、どちらからも文字を送れる |
| IPで接続 | 自動発見が通らない環境で、相手のIP指定後に双方向で送信でき、6秒以上経っても相手が一覧に残る |
| 部屋番号変更 | 異なる部屋の文字が表示されない。同じ部屋へ戻して接続し直せる |
| 発射を連続 | 表示が重複せず、送信側の「未達」が増えていないか記録する |
| 位置合わせ | Aの球と方向線が同じ物理位置に見える。発射位置・向きが両者で対応する |
| 位置合わせ解除 | 未設定側では相手の文字を手前に表示する |
| スリープ・リセンター | 該当端末の位置合わせが解除される。再接続・再設定後に送受信できる |
| アクセスポイントの端末分離 | 接続できないことを、アプリ停止と区別できる。端末分離のないLANでも比較する |
| インターネットがないLAN | Wi-Fi内の直接接続と端末内認識が継続する |

ブロードキャストが禁止された環境では[IP手動指定](lan-manual.ja.md)でも確認します。端末間のUDPそのものが禁止される環境では接続できません。別のLANでは動くが対象LANで相手が見つからない場合、未達カウントだけでは原因を特定できません。

## 診断資料の保存

アプリを動かしたまま次を実行します。2台ある場合は端末ごとに `--serial` を指定します。

```powershell
python tools/quest_device.py collect
```

`.work/quest-device/UTC日時/` に保存します。Gitの対象外で、自動送信しません。録音・画面画像は取得せず、logcatも対象アプリのPIDに限定します。アプリが停止している場合は自動再起動せず終了します。

- `report.json`: OS・機種情報、利用可能な認識処理時間の中央値/p95、取得エラー、収集中にプロセスが変わったか。
- `app-log.txt`: logcatバッファに残る直近最大5,000行の範囲から、対象PIDのログ。
- `app-memory.txt`: 取得時点のアプリメモリ。ピーク値を測ったものではありません。
- `battery.txt`: Androidのバッテリー状態。CPU/GPU温度そのものではありません。
- `installed-package.txt`: 導入済みアプリのバージョン・権限等。ローカルAPKのハッシュだけでは、実際に導入されたビルドを証明できないため、これと照合します。

ログのASR時間は、0.01秒単位に丸めた**認識処理部分だけ**です。無音判定の約0.45秒、処理待ち、表示までの時間を含みません。サンプルなしの場合は時間を0にせず未測定と記録します。`deviceTestsPassed`も未判定のままで、ログ取得成功を動作合格に置き換えません。

発話終了から表示までの遅延は別途測ってください。目標は72Hz維持、確定までのp95が約1秒以内ですが、達成済みではありません。冷間起動・15分後・30分後に同じ文で比較し、MR＋音声＋LANの同時利用で遅れが積み上がらないか確認します。モデル比較の詳細は[初期調査](revival-investigation.ja.md)を参照してください。

## 導入ツール自体の検証

```powershell
python -m unittest discover -s tools -p test_quest_device.py -v
```

9件のオフラインテストで、接続対象の曖昧さ、未承認端末、APK検査失敗、導入失敗、他アプリの起動拒否、ログのPID制限、プロセス変化、欠測値の扱いを確認しています。実際のQuestへの導入・起動・ログ取得も上記の範囲で確認しました。
