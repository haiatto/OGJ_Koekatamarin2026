# 同じ部屋でのMR位置合わせ

0.4.0では、同じWi-Fi内の各Questで現実の同じ2点を指定し、発射位置と向きを共有できます。クラウド、外部サーバー、共有アンカーサービスは使用しません。コントローラーを使う手動の位置合わせで、精度・追跡のずれは実機で未検証です。

## 操作

1. 全端末を0.4.0以降の同じ版に更新し、同じWi-Fi・部屋番号で「接続 / 切断」を押します。通信形式をversion 2に変更したため、0.3.0以前とは接続できません。
2. 全員が触れられる固定された目印AとBを決めます。水平距離を0.5〜5m離します。Aが原点、AからBへの水平な向きが前方になります。高さはAを基準にします。
3. MRで「位置合わせ」を選びます。右コントローラーをAに置き、右グリップを押します。続いてBに置き、右グリップを押します。ボタン選択の人差し指トリガーとは別の、握る側のボタンです。
4. 全員が同じA・Bを、同じコントローラーの向き・当て方で指定します。取得するのはコントローラーの追跡原点なので、先端だけ合わせて向きを変えるとずれます。
5. パネルに「位置合わせ済」が表示されます。相手の準備状態は約1秒間隔で更新します。Aの小さな球と前方を示す線が同じ場所に見えるか確認してください。
6. 発話またはサンプル発射で文字を飛ばします。両端末の位置合わせができていると、発射位置と向きを共有します。文字の表面は各プレイヤーへ向くため、異なる方向からも読めます。

Aボタンでパネルを隠すと、設定済みの目印も隠れます。指定途中は目印を表示します。「位置を解除」で解除でき、「位置合わせ済」を押すとやり直せます。

## 解除される条件と制約

- スリープ、ヘッドセット追跡の喪失、システムのリセンター、部屋番号変更、VRへの切替で位置合わせを解除し、その端末の表示中の文字と発話待ちキューを消します。復帰後は合わせ直します。スリープからの復帰ではLANにも再接続してください。
- アプリ再起動後への保存は行いません。長時間の追跡ずれを自動修正する機能もありません。
- 自分か送信側が未設定の場合やVRモードでは、相手の文字を受信側の手前から発射します。VRの共有座標は未実装です。
- 送信するのは確定テキスト、色、一意なイベントID、位置合わせの有無、発射位置、水平な向きです。音声や空間の画像は送信しません。
- 通信遅延を補正していないため、文字の到着時刻と移動位置には遅れが出ます。物理衝突、キャラクター、共有物体の状態同期はありません。
- 各共有座標成分は±50m、向きは±180度に制限し、NaN・無限大などは拒否します。部屋番号は認証ではありません。

## 検証

Windows Editorで、異なる原点・向きを持つ2端末間の座標変換と逆変換、不正な測定値の拒否をテストしました。実UDPソケットで発射位置・向きの送受信と、遅れてまとめて届いた2イベントを両方受信すること、再送を重複表示しないことを確認しました。

受信は最大4件の短い集中到着を許容し、その後は1秒あたり5件分を補充します。処理枠を超えた新規イベントにはACKを返さず、送信側の再試行を待ちます。音声認識結果も最大8件まで待機させ、発射間隔中の確定結果を即座に捨てないようにしました。音声OFFで待機分を消します。

Quest実機間の位置精度、Wi-Fi、再センタリング通知、読みやすさは未検証です。
