# MRの当たり判定と表示・サイズ設定（0.10.0）

## 0.10.0: ライブメッシュへの変更

UXR.QuestMeshing 1.5.1を埋め込みパッケージとして導入。MRの起動時にDepth APIから
周囲の形状を取得し、通常のMeshCollider（レイヤー9）へ反映する。
Space Setupや保存済みScene Modelは読み込まない。空間データの権限は必要。
以下の「現在の衝突対象」以降にある保存済み部屋の説明は0.9.1までの記録。

- 「空間線」は実際のライブMeshColliderの三角形の辺を表示する。表示OFFでも衝突は有効。
- 「空間再取得」は現在の形状・当たり判定・線を破棄し、見回して作り直す。
- MRでは音声入力の開始後に自動取得。VR・アプリの一時停止中は深度取得と部屋の衝突を止める。
- リセンター・トラッキング喪失でも古い形状を破棄する。再開後は周囲を見回す。
- 声の5層表示、固定BoxCollider、発射速度・重力・寿命・サイズ設定は維持する。
  メニューとの衝突も引き続き除外。声同士は衝突する。
- 保存済みの部屋との重複Colliderは生成しない。セッション間で形状は保存しない。

最初の設定は8cmボクセル、160×80×160（12.8×6.4×12.8m、トラッキング原点中心）、
取り込み距離0.5〜4m、深度からの形状更新10Hz目標、メッシュ・Collider更新2Hz目標、
三角形上限65,536。数値は設定値であり実測性能ではない。NavMesh生成は使用しない。
視界外の既取得形状は保持されるが、未観測範囲や動いた物の除去は保証されない。
Meta OpenXRの手の除去を要求する。手以外の人・動物の除去を保証しない。

上流に、空形状時の古いCollider除去、クリア中の非同期処理結果の破棄、深度再開、
GPU範囲チェックなどの局所修正を加えた。
[変更記録](../QuestApp/Packages/com.uralstech.uxr.questmeshing/KOEKATAMARIN-CHANGES.md)。
他のEnvironmentDepthManagerやAROcclusionManagerを同時に追加して深度を取得しない。

### 実機で確認すること

1. 空間データを許可し、「空間線 ON」で壁・床・机をゆっくり見る。水色の線が増えるか。
2. 視線を外して戻しても既取得の壁が残るか。「サンプル発射」で実際に当たるか。
3. 椅子などを移動し、空いた場所と移動先を見直す。古い当たり判定が残らないか。
4. 「空間再取得」で線と衝突が一旦消え、新しい形状を取得するか。
5. VR→MR、ヘッドセットの休止→復帰で再取得できるか。
6. ReazonSpeechと空間線を同時に使った時の反応・フレームレート・熱・継続負荷。

## 0.9.1までの方式と調査記録

## 現在の衝突対象

- メニューのCubeにはポインター操作用のBoxColliderがあるが、声（レイヤー8）とメニュー（レイヤー0）の衝突は起動時に除外する。声はメニューで止まらない。
- 声同士は衝突する。認識訂正による多重発射があると、先に飛んだ声に当たる可能性もある。[音声処理の既知の問題](offline-speech.ja.md)。
- 声は原作と同じ固定BoxCollider。100%で幅1m×高さ1m×厚さ0.2mで、文字数や字形に合わせた形ではない。見た目に何も当たっていなくても、この箱が接触する場合がある。
- 部屋（レイヤー9）はMRUKでQuestの保存済み空間データから生成する。グローバルメッシュがあればそのMeshCollider、なければ壁・床などの面と家具などのBoxColliderを使う。常時更新するカメラ映像からの物体認識ではない。
- MRからVRへ移ると部屋の当たり判定を無効にし、MRへ戻ると再度有効にする。
- 頭・プレイヤー移動に、この部屋データで移動を止める処理はない。

保存済みの空間形状のずれ、家具の箱による粗い表現、声の固定サイズ、声同士の接触が、予想外の引っかかりの候補。今回のコード調査だけで実機の原因を一つに確定していない。原作の文字シェーダーは深度に関係なく描くため、壁の手前・奥という見た目だけでは接触位置が分かりにくい場合もある。

## 空間線 ON / OFF

パネル下部の「空間線 OFF」を押すと水色の半透明の線を表示する。0.9.1では形状が未取得なら部屋読込を試み、生成前は「空間線 待ち」と表示する。状態欄には生成形状・辺・未取得の数を表示する。部屋読込が15秒以上続く場合は、スキャンした場所・空間設定の確認を案内し、SDKの読み込み完了を引き続き待つ。位置の追跡状態をアプリが確定診断する表示ではない。MR限定で、VRへ切り替えると隠れ、MRへ戻ると再表示する。起動時はOFF。

表示するのは、実際のMeshColliderの三角形の辺、またはBoxColliderの中心・寸法に対応した12本の辺。表示専用の物体にはColliderを追加しない。表示を消しても部屋への衝突は有効のまま。部屋再読込やMRUKのアンカー差し替えにも追従する。声自身の箱はこの表示には含めない。

線は透過描画・深度書き込みなしで、奥の形も透けて見える。実際の家具と線の位置を比較するための表示で、現実の物体を塗りつぶさない。密なメッシュの見やすさ・左右の目での表示・Questでの追加描画負荷は装着して確認する。

## 文字サイズ

パネル下部の「文字 100% →」で100→150→200→25→50→75→100%と切り替える。初期値100%は原作移植の寸法。設定は端末内に保存する。

5層TextMeshの厚み・文字の大きさ・固定BoxColliderを同じ倍率で変える。発射速度、重力、寿命、色、フォント、認識と発射のタイミングはサイズ設定で変わらない。すでに飛んでいる文字はそのままで、次に飛ぶ文字から適用する。

これは各端末の設定で、相手から届く文字にもその端末で選んだサイズを使う。送信側のサイズをネットワーク転送する機能ではなく、従来どおり物理状態の端末間同期もない。

## 確認する順序

1. 「空間線 ON」にして、壁・床・机の線が実物に合っているかを見る。
2. 音声を一時OFFにし、「サンプル発射」を間隔を空けて使う。声同士の衝突と部屋への衝突を切り分ける。
3. 100%と25%または50%で、同じ方向に発射して接触位置を比較する。
4. 表示OFFでも衝突すること、VRで線が消えてMRで戻ることを確認する。

## 0.9.0の実機報告と0.9.1の対応

2026-11-03、ユーザーから「空間線が見えない」と報告。対象アプリのログではQuest側のAnchorFrameworkが部屋の全アンカーを位置特定できないというエラーを繰り返した。描画そのものの故障と断定できず、スキャンした場所との一致も確認が必要。

0.9.1では未取得状態をON表示だけで済ませず、形状・辺数と読み込み状態を表示・ログ記録する。またMRUKが空のMeshオブジェクトを返す場合、グローバルメッシュありと判定せず壁・床・家具の形状へフォールバックする。線のデータがない状態から後で取得できた場合の復帰をテストする。

保存された部屋を位置特定できない原因が解消したとはまだ確認していない。部屋をスキャンした場所で周囲を見回してから「部屋読込」で再試行し、必要に応じてQuest側の空間設定を確認する。保存データの削除・再スキャンは自動では行わない。

## 事前スキャンはQuest全体の必須条件ではない

2026-11-03に公式資料を再確認。現在のアプリはScene Modelから部屋のColliderを作る方式なので、Space Setupで得たデータが必要。これは採用した方式の条件であり、Quest 3のMR全体で事前スキャンが必須という意味ではない。[Meta: Manage and query scene data](https://developers.meta.com/vr/documentation/unity/unity-mr-utility-kit-manage-scene-data/)。

Quest 3ではEnvironment Raycastingでライブの深度情報に対する交点・面の向きを取得できる。現在のMRUKにもEnvironmentRaycastManagerが含まれるが、このアプリではまだ使用していない。カメラ範囲外の判定には制約があり、Unityの部屋全体のMeshColliderが自動で生成される機能ではない。[Meta: Environment Raycasting](https://developers.meta.com/vr/documentation/unity/unity-mr-utility-kit-environment-raycast/)。

スキャン不要を基本とするなら、ライブ環境の問い合わせ結果を声の衝突・反射へ接続する追加実装と実機検証が必要。部屋全体を保存して使う方式と同じ範囲・物理挙動を保証しない。原作の固定BoxColliderとRigidbodyの挙動をどの程度保てるかを評価し、保存済み部屋方式との切替・併用を検討する。Depth API自体が通常の物理Colliderを提供するとは説明しない。[Meta: Depth API Overview](https://developers.meta.com/vr/documentation/unity/unity-depthapi-overview/)。
