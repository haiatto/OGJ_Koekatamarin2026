# MRの当たり判定と表示・サイズ設定（0.9.0）

## 現在の衝突対象

- メニューのCubeにはポインター操作用のBoxColliderがあるが、声（レイヤー8）とメニュー（レイヤー0）の衝突は起動時に除外する。声はメニューで止まらない。
- 声同士は衝突する。認識訂正による多重発射があると、先に飛んだ声に当たる可能性もある。[音声処理の既知の問題](offline-speech.ja.md)。
- 声は原作と同じ固定BoxCollider。100%で幅1m×高さ1m×厚さ0.2mで、文字数や字形に合わせた形ではない。見た目に何も当たっていなくても、この箱が接触する場合がある。
- 部屋（レイヤー9）はMRUKでQuestの保存済み空間データから生成する。グローバルメッシュがあればそのMeshCollider、なければ壁・床などの面と家具などのBoxColliderを使う。常時更新するカメラ映像からの物体認識ではない。
- MRからVRへ移ると部屋の当たり判定を無効にし、MRへ戻ると再度有効にする。
- 頭・プレイヤー移動に、この部屋データで移動を止める処理はない。

保存済みの空間形状のずれ、家具の箱による粗い表現、声の固定サイズ、声同士の接触が、予想外の引っかかりの候補。今回のコード調査だけで実機の原因を一つに確定していない。原作の文字シェーダーは深度に関係なく描くため、壁の手前・奥という見た目だけでは接触位置が分かりにくい場合もある。

## 空間線 ON / OFF

パネル下部の「空間線 OFF」を押すと水色の半透明の線を表示する。部屋未読込なら先に「部屋読込」を押す。MR限定で、VRへ切り替えると隠れ、MRへ戻ると再表示する。起動時はOFF。

表示するのは、実際のMeshColliderの三角形の辺、またはBoxColliderの中心・寸法に対応した12本の辺。表示専用の物体にはColliderを追加しない。表示を消しても部屋への衝突は有効のまま。部屋再読込やMRUKのアンカー差し替えにも追従する。声自身の箱はこの表示には含めない。

線は透過描画・深度書き込みなしで、奥の形も透けて見える。実際の家具と線の位置を比較するための表示で、現実の物体を塗りつぶさない。密なメッシュの見やすさ・左右の目での表示・Questでの追加描画負荷は装着して確認する。

## 文字サイズ

パネル下部の「文字 100% →」で100→150→200→25→50→75→100%と切り替える。初期値100%は原作移植の寸法。設定は端末内に保存する。

5層TextMeshの厚み・文字の大きさ・固定BoxColliderを同じ倍率で変える。発射速度、重力、寿命、色、フォント、認識と発射のタイミングはサイズ設定で変わらない。すでに飛んでいる文字はそのままで、次に飛ぶ文字から適用する。

これは各端末の設定で、相手から届く文字にもその端末で選んだサイズを使う。送信側のサイズをネットワーク転送する機能ではなく、従来どおり物理状態の端末間同期もない。

## 確認する順序

1. 「空間線 ON」にして、壁・床・机の線が実物に合っているかを見る。
2. 音声を一時OFFにし、「サンプル発射」を間隔を空けて使う。声同士の衝突と部屋への衝突を切り分ける。
3. 100%と25%または50%で、同じ方向に発射して接触位置を比較する。
4. 表示OFFでも衝突すること、VRで線が消えてMRで戻ることを確認する。
